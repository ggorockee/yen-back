# 돌려받엔 (yen-back) 기획안 v0.1

- 작성일: 2026-11-15
- 스택: Flutter (리뷰맵과 동일: Riverpod, google_mobile_ads, Firebase) / Go (Fiber) 서버
- 상태: 초안. "추측" 또는 "확인 필요"로 표시된 항목은 출시 전에 검증해야 함
- 시점 메모: 일본 리펀드 방식은 2026-11-01부터 이미 시행 중. 사용자가 새 제도에 헷갈려하는 지금이 가장 수요가 큰 시기라서, 최대한 빨리 출시하는 것이 핵심임

## 0. 제도 팩트 시트 (출시 전 공식 출처 재확인)

| 항목 | 내용 | 출처 | 상태 |
|---|---|---|---|
| 시행일 | 2026-11-01 구매분부터 리펀드 방식 적용. 10-31까지 구매분은 기존 방식 | 일본 관광청, 나리타공항 공지 | 확인됨 |
| 결제 방식 | 매장에서 세금 포함 가격으로 결제 → 출국 시 세관 반출 확인 → 판매점(또는 위탁사업자)이 소비세 환급 | 관광청 "What is the Refund Method?" | 확인됨 |
| 세관 확인 기한 | 구매일로부터 90일 이내 출국 시. 기산일(구매 당일인지 다음 날인지)은 자료마다 다름 | 일본 국세청 팸플릿 | 기산일 확인 필요 |
| 확인 순서 | 짐을 부치기 전에 세관 확인(키오스크)을 받아야 함. 실물 제시를 요구받을 수 있음 | 관광청, 공항 안내 | 확인됨 |
| 최소 구매액 | 같은 날, 같은 매장에서 세전 5,000엔 이상 | 여행 매체 다수 | 국세청 원문 확인 필요 |
| 일반 물품/소모품 구분 | 폐지되어 합산 가능. 소모품 50만 엔 상한과 특수 포장 요건도 폐지 | 여행 매체 다수 | 국세청 원문 확인 필요 |
| 일본 내 소비 | 식품, 화장품 등을 일본 안에서 소비하면 환급 불가 | 관광청 | 확인됨 |
| 환급액 | 소비세 10% (식품 등 경감세율 8%). 판매점이나 위탁사업자가 수수료를 뗄 수 있고, 환급 시점과 수단은 매장마다 다름 | 관광청 | 수수료율 확인 필요 |
| 한국 입국 면세한도 | 1인당 미화 800달러. 술, 담배, 향수는 별도 한도 | 한국 관세청 | 별도 한도 세부 수치 확인 필요 |
| 환율 API | 한국수출입은행 Open API (oapi.koreaexim.go.kr). 영업일 11시 전후 갱신. 엔화는 100엔 단위(JPY(100))로 제공 | 공공데이터포털 | 단위 표기는 실제 응답으로 확인 필요 |

**설계에 미치는 영향**
- 환급액은 "최대 예상치"로만 표시하고, "수수료에 따라 실제 금액은 달라질 수 있음"이라는 문구를 반드시 넣음
- 경감세율(8%)과 표준세율(10%)을 품목 단위로 고를 수 있어야 함
- 90일 기한은 보수적으로 계산함(구매 당일을 1일차로 셈). 그래도 핵심 알림은 출국일 기준으로 보냄

## 1. 서비스 정의 및 핵심 가치

**정의**: 일본에서 쇼핑할 때 엔화 가격을 원화로 바로 바꿔 보여주고, 리펀드 방식 면세 환급 조건(5,000엔), 환급 예정액, 세관 확인을 놓치지 않도록 챙겨주는 여행 쇼핑 비서

| 핵심 가치 | 사용자 문제 | 해결 |
|---|---|---|
| 즉시 환산 | 세금 포함 가격인지 아닌지 헷갈리고, 원화로 얼마인지 모름 | 하나만 입력하면 세포/세전/원화를 동시에 보여줌 |
| 환급 조건 충족 | "조금만 더 사면 면세인데"를 매장에서 계산하기 어려움 | 매장별 장바구니에 "5,000엔까지 ○○엔 남음" 표시 |
| 돈 돌려받기 | 새 제도에서는 세관 확인을 안 받으면 이미 낸 세금을 못 돌려받음 | 출국일 기준 알림과 공항 체크리스트 |
| 귀국 리스크 | 800달러 초과로 세관에서 가산세를 낼 위험 | 누적 구매액을 USD로 환산해 경고 |

## 3. 경쟁 앱 분석 (추측, 실제 스토어 조사 필요)

| 구분 | 예시 유형 | 강점 | 약점 | 돌려받엔 차별점 |
|---|---|---|---|---|
| 범용 환율 계산기 | 각종 환율 계산기 앱 | 통화 수가 많고 빠름 | 일본 세금, 면세 개념이 없음 | 세포/세전 동시 표시, 리펀드 추적 |
| 은행/카드사 앱 | 트래블 카드 앱 | 실제 결제 환율, 충전 | 면세 조건 관리 기능 없음 (추측) | 카드와 무관하게 쓸 수 있고, 매장별 집계 |
| 여행 가계부 | 트리플, 여행 가계부 앱 | 지출 기록, 일정 | 5,000엔 조건이나 세관 기한 기능 없음 (추측) | 면세 환급에 특화된 가계부 |
| 일본 공식/공항 안내 | 관광청, 공항 웹 | 정확한 정보 | 개인 구매를 추적할 수 없음 | 내 구매에 맞춘 개인화 알림 |

- 조사 항목 (확인 필요): 국내 스토어에서 "일본 면세", "엔화 계산기", "소비세 환급" 검색 상위 10개 앱의 기능, 평점, 업데이트일
- 위험: 11월 시행 이후 경쟁 앱이 같은 기능을 빠르게 붙일 수 있음. 그래서 출시 속도가 차별점보다 중요함

## 4. 기능 명세

### MVP (4~6주)

| ID | 기능 | 상세 | 수용 기준 |
|---|---|---|---|
| M1 | 엔화 계산기 | 엔화 입력 → 세포가, 세전가, 원화를 동시에 표시. 입력값이 세포인지 세전인지 토글. 세율 10%/8% 선택 | 숫자 키패드에서 결과가 즉시 갱신되고 오프라인에서도 동작 |
| M2 | 매장별 장바구니 | 매장(이름, 날짜)을 만들고 품목을 추가. 세전 합계와 "5,000엔까지 ○○엔 남음" 표시. 날짜가 다르면 별도 매장으로 처리 | 5,000엔 달성 시 시각 피드백 |
| M3 | 영수증 등록 | 사진 촬영 또는 갤러리에서 첨부(기기 로컬). 매장에 연결하고 세포 금액, 세액을 수동 입력 | 사진이 서버로 전송되지 않음 |
| M4 | 환급 예정액 합산 | 조건을 충족한 매장의 소비세 합계를 "최대 예상 환급액"으로 표시(엔/원). 수수료 안내 문구 포함 | 미충족 매장은 제외하고 별도 표시 |
| M5 | 출국 리마인드 | 출국일, 시간, 공항 입력 → 로컬 알림 (D-1 저녁, 당일 공항 도착 예상 시각). 공항 체크리스트 제공 (짐 부치기 전 키오스크, 여권, 실물) | 앱을 꺼도 알림이 오고, 90일이 넘은 구매는 경고 |
| M6 | 한국 면세한도 경고 | 전체 구매액을 USD로 환산해 800달러 대비 진행률 표시. 술, 담배, 향수는 카테고리 태그로 별도 안내 | 초과 시 경고 배너 표시 (자진신고 감면 안내는 확인 필요) |
| M7 | 오프라인 환율 캐시 | 마지막으로 받은 환율과 기준일을 로컬에 저장. 기준일을 항상 화면에 표시 | 비행기 모드에서도 계산 가능 |
| M8 | 광고와 광고 제거 결제 | 배너, 전면광고, 광고 제거 1회 구매 | 구매 복원 동작 |

### 2차

| 기능 | 이유 |
|---|---|
| 영수증 OCR 자동 입력 (온디바이스: iOS Apple Vision, Android ML Kit) | 2026-11-15 구현 완료. 합계·소비세(세율별)·날짜·매장 자동 입력 후 사용자 확인, 실제 영수증으로 정확도 추가 검증 필요 |
| 동행자별 구매 분리 (가족 모드) | 면세한도가 1인당 적용되기 때문 |
| 홈 화면 위젯 (오늘 환율) | 재방문 유도 |
| 환율 알림 ("100엔 = ○○원 이하면 알림") | 서버 푸시(FCM) 필요 |
| 여행 기록 아카이브와 내보내기 (이미지/CSV) | 블로그 공유로 바이럴 유도 |
| 다국어 (영문) | 시장 확장 |

### 보류

| 기능 | 보류 사유 |
|---|---|
| 회원가입, 클라우드 동기화 | 개인정보, 비용, 심사 부담. MVP에 필요 없음 |
| 실제 환급 신청 연동 | 사업자별 API가 공개되어 있는지 알 수 없음 (확인 필요) |
| 카드 결제 환율 반영 | 카드사마다 수수료 구조가 달라 복잡함 |
| 매장 지도, 면세점 DB | 데이터 유지 비용이 큼 |

## 5. 화면 목록과 사용자 흐름

| ID | 화면 | 와이어프레임 설명 |
|---|---|---|
| S0 | 온보딩 (3장) | 1) 새 리펀드 제도 한 장 요약 2) 5,000엔과 90일 규칙 3) 출국일 입력(건너뛰기 가능) + 알림 권한 요청 |
| S1 | 계산기 (홈, 탭1) | 상단: 큰 엔화 입력창과 [세포/세전] 토글, [10%/8%] 칩. 중단: 원화 큰 글씨, 세전/세포/세액 3줄. 하단: 커스텀 숫자 키패드와 [장바구니에 담기] 버튼. 최상단 작은 글씨로 "기준 환율 100엔=○○원 (11/14 기준)" 표시 |
| S2 | 매장 목록 (탭2) | 카드 리스트. 각 카드에 매장명, 날짜, 세전 합계, 진행 바(5,000엔), 상태 배지(달성/○○엔 남음). FAB로 새 매장 추가 |
| S3 | 매장 상세 | 품목 리스트(이름, 가격, 세율), 합계, 영수증 썸네일, [영수증 추가] 버튼 |
| S4 | 영수증 등록 | 카메라 또는 갤러리 → 금액 입력 폼 → 저장 |
| S5 | 내 여행 대시보드 (탭3) | 총 지출(엔/원/USD), 최대 예상 환급액, 800달러 진행 바, 출국 D-day, 체크리스트 진입 버튼 |
| S6 | 출국 체크리스트 | 공항, 출국 시각, 할 일 체크(짐 부치기 전 키오스크, 여권, 실물 지참) |
| S7 | 설정 (탭4) | 출국일, 알림, 광고 제거 구매/복원, 제도 안내와 출처 링크, 면책 문구, 개인정보처리방침 |

**주요 흐름**
1. 첫 실행: S0 → 출국일 입력 → S1
2. 쇼핑: S1에서 가격 입력 → [담기] → 매장 선택 또는 새로 만들기 → S2에서 남은 금액 확인 → 결제 후 S4에서 영수증 촬영
3. 출국: D-1 알림 → S6 체크리스트 → 공항 키오스크 → 체크 완료
4. 귀국: S5에서 800달러 초과 여부 확인 → 초과 시 신고 안내 문구 표시

## 6. 시스템 아키텍처

서버가 하는 일은 환율 캐시 하나뿐임. 나머지는 모두 기기 로컬에서 처리하므로 비용과 개인정보 부담이 최소화됨.

| 구성요소 | 선택 | 역할 | 비고 |
|---|---|---|---|
| 모바일 | Flutter, Riverpod, sqflite(SQLite), flutter_local_notifications, google_mobile_ads, in_app_purchase | 계산, 장바구니, 영수증, 알림 모두 로컬 | 리뷰맵 코드와 패턴 재사용 |
| API 서버 | Go Fiber, 기존 GKE 클러스터 (Helm + ArgoCD GitOps, Istio, yen-back.woohalabs.com) | 환율, 제도 상수, 활동 이벤트 API | 응답에 캐시 헤더 설정. Cloud Run 대신 기존 인프라 재사용 (변경, 2026-11-15) |
| 수집 배치 | 서버 안 스케줄러 (COLLECT_INTERVAL=30m) + 수동 /internal/collect | 저장된 날짜까지 거슬러 조회, 실행당 호출 몇 회 | 값이 비어 있으면 기존 값을 유지 |
| 저장소 | MVP는 메모리 저장소 (재시작 시 첫 요청에서 자동 재수집). Postgres 저장소 구현 포함, DATABASE_URL로 전환 | 일자별 환율 이력 | 신규 비용 0원 |
| 푸시 | MVP는 로컬 알림만 사용. 2차에 FCM 도입 | 출국 리마인드 | 서버에 출국일을 보낼 필요가 없음 |
| 원격 설정 | 서버 GET /v1/rules (Firebase 설정 파일 없이 동작하도록 변경) | 세율, 5,000엔 기준, 90일, 800달러, 공지 배너 | 서버 배포만으로 반영, 앱은 캐시 + 기본값 |
| 모니터링 | Prometheus /metrics(9090, 비공개) + ServiceMonitor, Grafana 대시보드(uid yen-back), 알림 규칙 7종, blackbox 외부 접속 검사, JSON 구조화 로그 | 서버 상태, API, 환율 수집, 앱 활동(플랫폼·버전·이벤트) | infra 레포 kube-prometheus-stack에 연동 |

**환율 수집 정책**
- 수출입은행 응답이 빈 배열이면(비영업일, 11시 이전) 저장하지 않고 직전 영업일 값을 그대로 제공
- 앱 응답 JSON에 기준일(base_date)과 신선도 정보를 포함해서, 앱이 "○일 기준"을 항상 표시
- 수출입은행이 2영업일 이상 실패하면 운영자에게 알림. 2차 소스(다른 공개 환율 API)는 추후 검토 (확인 필요)
- 엔화는 100엔 단위이므로 1엔 단위로 정규화해서 저장
- 고시 환율(매매기준율)은 실제 카드 결제 환율과 다르다는 안내 문구를 표시

API 응답 예시

```json
{
  "base_date": "2026-11-14",
  "fetched_at": "2026-11-14T02:12:00Z",
  "rates": {
    "JPY": { "krw_per_unit": 9.21, "deal_bas_r_raw": "921.35", "unit": 100 },
    "USD": { "krw_per_unit": 1388.5, "deal_bas_r_raw": "1,388.5", "unit": 1 }
  },
  "stale": false
}
```

(위 수치는 형식 예시이며 실제 환율이 아님)

## 7. 데이터 모델

### 서버 (Postgres)

| 테이블 | 컬럼 | 설명 |
|---|---|---|
| exchange_rates | id, base_date (date), currency (JPY/USD), krw_per_unit (numeric), raw_value (text), source, fetched_at | (base_date, currency) 유니크 |
| collector_runs | id, run_at, status (ok/empty/error), message | 수집 실패를 추적 |

### 앱 로컬 (SQLite / sqflite)

| 엔티티 | 주요 필드 | 설명 |
|---|---|---|
| Trip | id, name, departure_at, airport, created_at | 여행 단위. MVP에서는 활성 여행 1개만 |
| Store | id, trip_id, name, purchase_date | 같은 날 + 같은 매장 = 하나의 면세 판정 단위 |
| Item | id, store_id, name, price_yen, price_mode (incl/excl), tax_rate (8/10), category (general/alcohol/tobacco/perfume) | 세전/세포 값은 계산해서 표시 |
| Receipt | id, store_id, image_path (로컬), total_incl_yen, tax_yen, created_at | 사진은 앱 전용 디렉터리에 저장 |
| RateCache | base_date, jpy_krw, usd_krw, fetched_at | 마지막 1건 + 최근 7일 |
| ChecklistState | trip_id, item_key, done | 출국 체크리스트 |
| Entitlement | ad_free (bool), purchase_token | 광고 제거 상태 |

**계산 규칙**
- 세전 = 세포 ÷ (1 + 세율). 엔 단위 반올림 규칙은 매장마다 다를 수 있음 (확인 필요)
- 매장 판정: 세전 합계가 5,000엔 이상이면 환급 대상
- 최대 예상 환급액 = 대상 매장 세액의 합 (수수료 차감 전)
- 면세한도 = 전체 세포 합계 × (JPY→KRW) ÷ (USD→KRW). 판정은 실제 구매가(세포) 기준으로 함 (관세청 기준 확인 필요)

## 11. 스토어 등록용

**앱 이름**: 돌려받엔 - 일본 면세 환급 계산기

**짧은 설명 (80자 이내)**: 엔화를 원화로 바로 계산하고, 바뀐 일본 면세 환급까지 챙겨드려요.

**소개문**

2026년 11월부터 일본 면세가 '리펀드 방식'으로 바뀌었어요. 이제는 매장에서 세금까지 모두 내고, 출국할 때 세관 확인을 받아야 돌려받을 수 있어요. 돌려받엔이 그 과정을 챙겨드려요.

- 엔화 가격을 입력하면 원화, 세전가, 세금이 한 번에 보여요
- 매장별 장바구니로 "면세 5,000엔까지 얼마 남았는지" 바로 확인해요
- 영수증을 찍어두면 돌려받을 예상 금액을 모아서 보여드려요
- 출국 전날과 당일, 세관 확인을 잊지 않도록 알려드려요
- 귀국할 때 한국 면세한도 800달러를 넘는지 미리 확인해요
- 비행기 모드에서도 마지막 환율로 계산할 수 있어요
- 영수증 사진은 내 폰에만 저장돼요

※ 돌려받엔은 정부기관과 관련 없는 비공식 앱이에요. 실제 환급액은 매장과 환급 사업자의 수수료에 따라 달라질 수 있어요.
